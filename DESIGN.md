# Bandsy — design (settled 12 Sep 2026)

Personal IELTS Academic prep app. Single user, local, private. Computer-delivered IELTS is the target; the app mimics its screens.
Provisional test date: **31 Dec 2026**. No baseline band yet. The real product requirement is motivation: every session ends with a number that moves.

## Corpus and extraction
- Source: `./Cambridge-lists-main` — Cambridge IELTS 1–15 (PDF + audio per test). Books 6, 7, 9, 10, 12, 13, 14 are scans (no text layer). Audio is mp3 except book 8 (wma) and 15 (m4a). Folder is gitignored (2.1 GB).
- Extract books **10–15 first** (24 tests). Book 15 (text layer, newest) is the pipeline's test case. 1–9 only if material runs out.
- Pipeline (revised 13 Sep after the first run blew through the Pro limit): **Tesseract OCR** reads every page locally (passages, transcripts, writing prompts and the section map come straight from OCR — no model). A model only structures question groups and speaking frames from the OCR *text* (~6k tokens a call, Sonnet) and reads the 8 answer-key page images (vision). ≈150k tokens per book. Claude Code's output filter blocks long verbatim passage text, which is another reason passages never pass through a model.
- Tables, forms and flow charts are re-read from the page image (OCR interleaves table columns), as is any question group whose `[[n]]` gaps don't match its question numbers (model dropped a gap). A re-read is kept only if its gaps match exactly. ~8k tokens per such group, a handful per book.
- Damaged scan pages (Tesseract word confidence: 3+ lines with a quarter of words under 60) get their passage paragraphs re-read from the page image one at a time; a re-read is kept only if its words match the OCR's readable words. Audioscript parts missing from a scan (Cambridge 13 Test 3 Section 2) are transcribed from the book's own recording with local Whisper and marked as automatic. Paragraph letters come from the image when OCR's don't match the questions' "A–G".
- Verification: free validators (question numbers complete and consecutive, `[[n]]` gaps match question numbers, letter questions have options, table rows have equal cell counts). `--verify` adds a second model pass and diffs it. No review UI; a "this question is broken" button in practice + hand-editing the JSON.
- Figures (Task 1 charts, Listening maps): whole page image in `content/camNN/figures/`, referenced from the JSON. Bbox cropping is a later luxury.
- Every question tagged with its IELTS question type (matching headings, T/F/NG, Y/N/NG, matching information/features, sentence/summary/note/table/form completion, MCQ, short answer, diagram/map labelling).
- Extraction never runs on a fallback model — if rate-limited, it stops and waits. Providers are `claude:<model>` (Claude Code subprocess, subscription) or `ollama:<model>`; `--text` and `--vision` are both required, no defaults.
- The vocabulary book (`Check Your English Vocabulary for IELTS`) is extracted into themed word lists.

Output: **one JSON file per test in `content/`**, git-tracked, hand-editable, idempotent import. SQLite holds attempts and progress only.

## Architecture
- **Vite SPA** (the app) + **one Node process** (`server.js`: static, API, SQLite, provider keys, examiner state; spawns the sidecar) + **one Python sidecar** (`sidecar/audio.py`: faster-whisper + Kokoro ONNX on CPU, port 3002). `npm run dev` starts all three.
- **Model providers** behind one adapter interface (`complete`, `stream`, `vision?`):
  - `claude-code`: Claude Code subprocess using the Claude Pro login (`claude -p … --output-format json`, `--resume` for conversations). No separate API key. Not an officially supported backend — the adapter is the insurance.
  - `openai-compatible`: OpenAI, Groq, Ollama, Gemini and others via base URL + key. Model lists fetched live where the provider offers `/models`.
  - `anthropic` API if a key is ever added.
- **Model selector per job — extraction (vision-capable only), writing grading, examiner, small tasks (vocab, error cards). No defaults; each set at setup.**
- **Rate limit hit mid-session: stop and tell the user**; they wait or switch model. Nothing silently downgrades.

## Modules
**Listening** — exactly like the test: audio plays once, questions below, typed answers, auto-marked from the extracted key. Transcript only after "check transcript". Section is the drill unit; no per-question timestamps.

**Reading** — full CD-IELTS mimic: split screen (passage | questions), independent scroll, highlight + notes, flag-for-review, review screen listing all 40 answers, timer. Drills reuse the screen with the timer hidden. Click-to-save vocabulary while reading; model defines the word in context.

**Writing** — exact CD-IELTS editor: task left (with figure for Task 1), plain text right, live word count, spell-check off, 60 min shared across both tasks. After submit: band per criterion (TA/TR, CC, LR, GRA) against the public band descriptors, inline error marks with hover explanations, and a band-8 rewrite side-by-side.

**Speaking** — cascade: browser mic → STT (faster-whisper base.en, CPU) → examiner → TTS (Kokoro, British voice), all local via `sidecar/audio.py`. Measured on this machine (13 Sep): TTS ≈ 3 s per sentence, STT ≈ 3.5 s per 30 s of speech, a Sonnet call via the CLI ≈ 10–12 s — so a model *in* the turn loop would mean ~17 s pauses. **Exam mode therefore runs as a scripted state machine over the extracted Cambridge frame**: the next utterance is synthesized while the candidate is still answering and transcription runs in the background, so a turn costs the upload (measured 0.0 s). The model is used only for Part 3 follow-ups (generated during the answer, asked one question later so they reference what was actually said), tutor mode (model in the loop, latency accepted), and the final grading. Part 2: 1 min prep with notes, 2 min talk with hard cut. End-of-turn by silence detection (RMS threshold slider, 1.5 s), push-to-talk toggle. Feedback after: bands for Fluency & Coherence (whisper word timings → wpm, pauses), Lexical Resource, Grammatical Range & Accuracy; **Pronunciation "not assessed"**; corrections; band-8 answers for the weakest turns.
Tutor mode (toggle): free conversation on IELTS topics, corrections whenever.

## Learning loop
- **Diagnostic** split over the first 4 days, one module each, Listening first so day 1 ends with a real band.
- **Today screen**: countdown to test date, one pre-picked session button, band graph. Nothing else.
- **Rotation**: fixed weekly table weighted to the weakest module. 6 days/week, 30 min cap, Sunday = rest day, full mock section every 2nd Saturday. Adaptive selection only after ~4 weeks of data, if ever.
- **Word bank** (`#/vocab`): words saved by double-clicking in Reading passages (defined in context) plus the vocabulary book's 58 topic lists. No review session or scheduling — removed 13 Sep 2026 at the user's request; Writing/Speaking corrections live on their result screens.
- **Band graph**: L/R raw → band via the official conversion tables; W/S from the model; overall = mean rounded to the nearest 0.5 (IELTS rounding). Trend over single scores — model bands drift ±0.5.

## Build order — all six built 12–13 Sep 2026
1. Extraction pipeline ✓ (`pipeline/extract.py`): books 10–15 extracted (13–14 Sep 2026): all 24 Academic tests; Cambridge 10's two General Training tests are skipped by the map, same command per book (~400k–650k tokens for a scanned book with many lettered passages; Cambridge 12 took ~690k because its watermark garbles lines on every page). Answer keys are assigned to tests by print order, not the book's own test numbers (Cambridge 12 prints Tests 5–8). Audioscripts: speaker names printed in their own column are re-paired with their lines by word position; OCR debris is fixed by rule (| → I, margin Q-markers, stray full stops); garbled or dropped lines are rewritten from the book's own recording via local Whisper, aligned word by word, keeping names the scan printed cleanly. lines still garbled after that are filled from the recording between the clean lines around them, and the recording's own announcements are never let in. A misread that spells a real word ("sight hours", "taking pat") is corrected from the recording only when Tesseract itself doubted the word (confidence < 75), it is never heard in the part, and it isn't a spelling/ending variant — so clean British spellings stay. Two-column passages (Cambridge 10–12) are OCR'd per column, split at the measured white gutter with a small overlap (words assigned by centre), with subtitle lines that run across the gutter kept whole; with the title band taken from the full-width read; a short, empty or unfinished title triggers a page-image re-read of title + subtitle (subtitle shown under the title in the app). Option lists (headings, word boxes) are re-read from the page image when the instructions promise more keys than OCR found or an option holds non-words. At assemble time every text field passes `tidy()` (dash/margin-letter/brace debris) and `spell_fix()` — rule-based, no model: glued words split ("answerthese"), one Tesseract letter-confusion, one added or dropped letter, corrected only to a word in the 25k commonest (`pipeline/en_50k.txt`, hermitdave/FrequencyWords) and never a capitalised or dictionary word; `work/known_words.json` is the dictionary (confident OCR words + Whisper words + the 50k list, OCR junk in the list filtered out). `python pipeline/extract.py scripts --book N` rebuilds only the audioscripts (no model calls)

## Non-goals
Auth, multi-user, cloud, billing, authored lessons/curriculum, gamification, phoneme-level pronunciation, adaptive scheduling (v1), question-level Listening timestamps, a review UI for extraction.

- Garbled text is re-read from page images only on evidence: a non-word that Tesseract itself scored below 60, or below 85 and one or two letters from a common word (`misread`); instructions of TRUE/FALSE/NOT GIVEN and YES/NO/NOT GIVEN groups whose first line is garbled are rebuilt from the fixed template.
- Real-word misreads: transcripts swap a scan word for the word heard at the same spot when they differ by one letter of a pair Tesseract confuses (father/rather, vou/you, requlations/regulations) and the scan word isn't said nearby — never a British/American spelling or a Whisper mishearing (beech/beach). Passages: `python pipeline/extract.py proofread --book N --text <model>` (one paid text call per test, cached in `units/tN_proof.json`) lists suspected misreads; `assemble` applies only small letter-level fixes whose context is unique, and not to a word Tesseract read with 90+ confidence unless the change is a classic OCR shape (rn/m, l/i/t, T/I) — so the book's own wording ("Rapu Nui", "agriculture shocks") stays.
- Question text still ending in OCR scraps is re-read per group from the page image (`units/*.qtext{N}.json`); a gap number printed before its gap in a form cell is dropped at assembly; transcript scrap lines where the recording says nothing between two clean lines are dropped.
- A speaker's turn the scan cut short (no closing punctuation, or a clipped apostrophe: "SUSIE: Yes, but that’") is completed from the recording when three or more words are said between it and the next turn, never across announcements.
- Speaker names: misreads, lower-case and junk-prefixed names, names with a lost or misread colon, two-word names and names on their own line are normalised to the names each part really uses (`speakers()`); in two-person dialogues a turn that lost its name gets the other person's, and a turn the scan lost entirely is inserted from the recording (`alternate_turns()`). The app shows transcripts as turns, the name in bold beside the speaker's whole turn.
- `python pipeline/extract.py turns --book N --text <model>`: one text call per dialogue part where the same name still starts two turns in a row (cached in `units/tN_partP.turns.json`); the model only says on which numbered line each speaker's turn begins, and `apply_turns()` names the unnamed line between two same-name turns (mangled names at that line — "aint And", "coun Yeah", "evan: You" — are recognised as the name). Remaining same-name repeats are the speaker continuing after the recording's break, which the model confirms.

## Visual design

Swiss Neutral, from the D3 frame on the Pencil canvas: Manrope; `#EDEDEA` ground; white cards (24px radius) with no borders or shadows; `#111` ink with greys for everything secondary; one lime accent `#D9FF5C` (countdown card, Submit, key highlights); a white pill nav with the current page in black; big tight headings (72–96px, 800, negative tracking). Home follows the frame: a hero card for today's session with its stats and Start, a lime countdown card, a band card with nine-segment bars, and the band-over-time chart in monochrome (grey steps + dashes, direct labels). Exam screens use the same black chrome bar, but the paper itself stays plain white Arial to mimic CD-IELTS.
